# 平台支持政策（桌面限定）

> **单一事实源。** 本文档是 One-Line 当前阶段的平台范围唯一权威来源；任何玩法、原型、验收或文档描述与本文冲突时，以本文为准。
> 全项目当前采用**桌面优先政策**：仅支持 Windows 与 macOS 电脑浏览器，手机和平板统一由全局门禁拦截。

## 一、当前支持平台

- Windows 电脑浏览器；
- macOS 电脑浏览器。

## 二、当前不支持平台（统一暂缓）

- 手机；
- 平板；
- 移动浏览器；
- 移动触控交互；
- 长按；
- 移动端 X（excluded）输入；
- 小屏响应式适配；
- 横竖屏适配；
- 触控与页面滚动冲突处理；
- 各玩法单独补移动端方案。

## 三、移动端未来处理原则

移动端不属于当前 P4，也不建立 `P4B-M`。重新开启移动端工作的前提是：

```text
全部核心玩法和家族结构基本完成
→ 桌面玩法、交互、视觉与关卡体系稳定
→ 再单独立项进行全产品统一移动端重构
```

当前任何玩法任务都不得以「顺手兼容」为由增加移动端专用交互和临时响应式方案。已有移动端代码和 CSS 不需要删除或重构，只是不再扩展。

重新开启移动端工作必须经过新的产品立项；当前全局门禁不是最终移动端设计，不冻结任何移动端交互方案。

## 四、手机和平板访问行为

检测到不支持的移动设备后，只渲染一个全局提示页：

```text
请使用电脑体验

当前版本仅支持 Windows 或 macOS 电脑浏览器。
移动端将在全部玩法内容完成后统一适配。
```

- 不提供「继续进入」按钮；
- 不提供关闭按钮；
- 不允许通过旋转横屏绕过；
- 不允许通过较大移动端 viewport 绕过；
- 手机和平板访问正式页面、playtest 或 prototype 都统一显示提示；
- 提示页保持简洁，与 One-Line 当前暗色视觉体系一致；
- 页面必须在小屏中完整显示，不产生横向滚动；
- 不依赖游戏 Runtime；
- 不读取或写入正式进度、存档、奖励；
- 不挂载 App 和玩法 Session。

## 五、门禁实现（App 挂载之前）

门禁位于 root bootstrap（`src/main.jsx`），在 `createRoot` 渲染分支之前完成检测：

```text
main / root bootstrap
├── unsupported mobile → DesktopOnlyNotice
└── supported desktop → App
```

- 检测为移动设备 → **App 根本不 mount**，不初始化 Runtime / Session / 存档读取 / 事件监听；
- 设备判断是纯函数（`src/utils/detectMobile.js`），可注入、可测试，全项目**唯一判断入口**；
- 判定只依赖 `userAgentData.mobile`、User Agent、`platform` + `maxTouchPoints`，**不读取 viewport 宽度或 CSS media query**，桌面浏览器缩窄窗口不会被误判为手机。

## 六、与历史文档的关系

- 本项目级政策**取代**旧的移动端计划与验收口径；历史文档保留但不作为当前依据。
- [`mobile-refactor-plan.md`](./mobile-refactor-plan.md)（移动端体验重构计划）已封存为历史记录，其中结论在本政策生效后不再作为行动依据。
- 各玩法文档中残留的移动端、390×844、长按、方案 C 等旧计划均被本文档取代，不再进入当前阶段验收。
