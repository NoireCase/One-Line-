# Hidden / 极简线索 — Medium 阶段玩法设计文档

## 文档定位

本文档是 Hidden（极简线索）模式从 Easy（5×5）进入 Medium（7×7）的**玩法设计方案**，不是实现文档。

本文档的作用：

- 明确 Easy 阶段已完成什么、未完成什么
- 论证为什么 Medium 不能只是 Easy 的数量延伸
- 提出 7×7 作为 Medium 主方向的玩法设计
- 定义下一步 prototype 的范围和成功标准

本文档 **不是**：

- 实现计划
- 关卡入库清单
- 正式版本发布内容
- 代码改动指南

## 1. Easy 5×5 阶段复盘

### 1.1 已完成内容

Hidden Easy 10 关 (`hidden-demo-01` ~ `hidden-demo-10`) 建立了极简线索的核心玩法框架：

| 维度 | 覆盖内容 |
|------|---------|
| 核心机制 | 关键数字分段推理：每段 (a→b) 步数恰好 = b-a |
| 棋盘 | 5×5，四向正交移动，全盘覆盖，不重复 |
| 关键数字密度 | 5-6 个可见数字 / 25 格（~20-24% 可见，76-80% 隐藏） |
| 起点类型 | 角点、边点、中心点、内部非中心点 |
| 路径类型 | 蛇形扫描、不规则扫描、螺旋式、折返式、区域穿梭式 |
| 推理模式 | close pair 绕行、long segment 长段规划、全局前瞻 |
| 主题关 | 等长段节奏关（demo-10，四段全 close pair，统一节奏） |
| 解锁机制 | 逐关解锁，与 Classic / Diagonal 一致 |
| UI | 独立 HUD（显示路径进度而非分数）、独立 WinPanel（"推理完成！"）、独立配色（橘色系） |
| 规则 | 无道具、无星级、无金币、纯通关验证 |
| HP | 10（高容错） |

### 1.2 Easy 阶段覆盖的推理体验

| 体验类型 | 描述 | 代表关卡 |
|---------|------|---------|
| 入门引导 | 蛇形路径 + 分散关键数字，段长交替，空间约束明确 | demo-01 |
| 轻度绕行 | 起点在左下区域，第一段 1→6 仅隔 1 格却需走 5 步 | demo-04 |
| 折返推理 | 列扫描 + 折返，两段 close pair 绕行 | demo-02 |
| 全局前瞻 | 中心起点螺旋路径，5 个关键数字，段长 5/6/7/6 | demo-03 |
| 大绕行 | 中心起点，前两段都是邻格但需 7 步和 5 步绕行 | demo-05 |
| 终点迷局 | 中心起点，终点在角落，错误绕行会封死后段 | demo-06 |
| 边缘推理 | 边缘起点 + close pair 双段 | demo-07 |
| 长段穿行 | 内部起点，9→20 是 11 步超长段，全关无 close pair | demo-08 |
| 区域穿梭 | 右边缘起点，路径在棋盘左右区域间穿梭 | demo-09 |
| 等长闭环 | 四段全 close pair（extra≥4），13→19 是 8 步长段，统一节奏收尾 | demo-10 |

### 1.3 Easy 阶段的根本限制

5×5 棋盘的本质限制不在于"关数做不够"，而在于**推理空间的维度不足**：

| 限制 | 原因 |
|------|------|
| 无法做真正的区域分割 | 25 格划分 2 个区域已经是极限，最多 1 个通道。无法形成"多区域 + 多通道"的推理空间 |
| close pair 容易重复 | 5×5 上的绕行空间有限，close pair 的绕行路径只有少数几种拓扑结构 |
| long segment 容易变成硬绕路 | 长段在 5×5 上就是绕着走，缺少"区域选择"的空间意义 |
| 缺少前段对后段的干扰 | 5×5 路径短（25 步），前 10 步的选择很难对后 10 步产生不可逆的区域封锁 |
| 同质化风险高 | 继续做 5×5 → 更多 close pair → 更多 long segment → 玩家感觉"又是绕" |

## 2. 为什么 5×5 Medium 不能作为主路线

### 2.1 5×5 还能做哪些内容

如果继续 5×5，可以新增以下类型：

| 类型 | 预计可做 | 说明 |
|------|---------|------|
| CORNER_LOCK（简化版） | 2-3 关 | 关键数字放在角落附近，强制特定角落访问顺序 |
| LATE_GAME_TRAP（显式化） | 1-2 关 | demo-06 隐式涉及，此处显式设计"前期合理/后期封死" |
| BALANCED_DEDUCTION（简化版） | 1-2 关 | 2 个区域同时给约束，但板面太小，深度有限 |
| 起点/终点位置变化 | 1-2 关 | 同边起点、对角起点、邻角起点等变体 |
| **合计** | **5-8 关** | — |

### 2.2 为什么不足以支撑 Medium

- **数量不足**: 5-8 关远不到 Medium 阶段应有的体量（预期 10-15+ 关）
- **新意不足**: CORNER_LOCK 在 5×5 上非常浅（角落只有 4 个，约束少）；LATE_GAME_TRAP 在板面过小时不够隐蔽
- **体验趋同**: 即使换了起点位置和路径形状，玩家的核心推理仍然是"两个点很近但要绕"— 因为 5×5 的空间绕行就是唯一可做的事
- **不可实现**: AREA_SPLIT、MULTI_REGION_ROUTE、真正的 BALANCED_DEDUCTION 在 5×5 上都不可实现

### 2.3 5×5 的合理定位

5×5 可以作为：

- Easy 阶段的完整内容（10 关，已达成）
- 未来可能的补充关（如 Easy 追加 1-2 关特色主题，但不作为 Medium）

**5×5 不应该作为 Hidden Medium 的主路线。**

## 3. 7×7 Medium 的核心价值

### 3.1 "不只是更大"

7×7 带来的不是"尺寸 ×2"，而是**推理空间的维度增加**。

| 维度 | 5×5 Easy | 7×7 Medium |
|------|---------|------------|
| 棋盘格数 | 25 | 49 |
| 路径长度 | 25 | 49 |
| 可见关键数字 | 5-6 | 11-15（建议） |
| 分段数 | 4-5 | 8-14 |
| 平均段长 | 5-6 | 3-7 |
| 可划分区域 | ≤2 | 3-4+ |
| 可设置通道 | 0-1 | 1-3 |

### 3.2 质变点

| 质变 | 说明 |
|------|------|
| 从点到区域 | 5×5 上每个关键数字只是"一个点"；7×7 上关键数字可以标记"区域入口/出口" |
| 从局部绕行到全局规划 | 5×5 绕行是局部的（绕完就没了）；7×7 上前半段的路径选择会影响后半段哪些区域还能访问 |
| 从单通道到多通道 | 7×7 可以有 2-3 个狭窄通道，形成"必须从 A 区经过通道去 B 区"的约束 |
| 从单约束到复合约束 | 多个 close pair + 多个 long segment 可以自然交错，不需要人工堆砌 |
| 从"走对"到"安排顺序" | 核心推理从"这一段怎么绕"变成"这几个区域按什么顺序走" |

### 3.3 一句话概括

> **不只是走够步数，而是安排整张棋盘的通过顺序。**

## 4. 7×7 Medium 目标体验

### 4.1 玩家应该感受到的

在 7×7 Hidden Medium 中，玩家应该经历以下推理：

1. **看到一张大棋盘，上面散布着十几个数字**
2. **不是直接判断"这个点和那个点很近要绕"，而是判断"棋盘有哪些区域？数字分布在哪些区域？"**
3. **规划：哪些区域必须先去，哪些必须后去？**
4. **识别通道：哪些格子是连接两个区域的唯一通道？如果提前占用了会怎样？**
5. **警惕死路：角落和边缘的格子如果太晚去，会不会已经无法进入了？**
6. **全局协调：这一段多走了 2 步没关系，但会不会导致后一段少 2 步空间？**
7. **最终：不只是"每一段都走对了"，而是"整张棋盘的空间被合理分配了"**

### 4.2 玩家不应该感受到的

- 只是"更大的棋盘上更多 close pair"
- 只是"更长的一段要绕更远"
- 靠试错而不是推理就能过
- 看不出"为什么这关是这个难度"
- 解完了也不知道自己的推理对不对

## 5. Medium 新增 Archetype

### 5.1 类型总览

| Archetype | 占比建议 | 核心推理 |
|-----------|---------|---------|
| AREA_SPLIT | 30-40% | 区域分割 + 通道选择 |
| CORNER_LOCK | 20-30% | 角落/死角必须提前进入 |
| LATE_GAME_TRAP | 10-20% | 前半看似合理，后半被封死 |
| BALANCED_DEDUCTION | 20-30% | 多区域同时约束，全局协调 |
| MULTI_REGION_ROUTE | 20-30% | 区域遍历顺序推理 |

（百分比之和 > 100%，因为单关可以同时属于多个 archetype）

---

### 5.2 AREA_SPLIT

**玩家看到什么：**

棋盘被自然分为 2-3 个区域（如左右分区、上下分区、中心 vs 外围）。关键数字分布在各个区域。区域之间有 1-2 个狭窄通道（宽度 1 格）。

**玩家要思考什么：**

- 哪些关键数字在哪个区域？
- 如果先走完区域 A 再去区域 B，中间经过通道时，步数够不够？
- 如果先把通道填了，后面的区域还能不能进去？
- 关键数字之间的步数差暗示了"在区域 A 中需要消耗多少步、穿越通道需要多少步、在区域 B 中需要消耗多少步"

**好关标准：**

- 分区在视觉上有辨识度（不是数学上分区而是玩家一眼能看出"这是两片"）
- 通道数量恰好（1-2 个），位置明确
- 至少有一个关键数字标记通道入口或出口
- 错误的区域顺序会导致某段步数不够或走不完
- 正确的顺序是唯一解

**坏关风险：**

- 分区边界模糊，玩家看不出"这是两个区域"
- 通道太多，没有真正的瓶颈
- 分区变成了纯摆设，不影响推理
- 实际推理还是 close pair，只是换了个名字

---

### 5.3 CORNER_LOCK

**玩家看到什么：**

棋盘的四角或内部死角（如凹形结构尽头）有关键数字。这些位置一旦错过就很难回来，因为回去需要绕一大圈。

**玩家要思考什么：**

- 哪个角落的数字（关键数字或非关键数字段）必须尽早处理？
- 如果先走外围再去角落，会不会因为步数限制回不来？
- 这个角落的进入和退出是否只有一条路？

**好关标准：**

- 至少有一个角落必须在整条路线的前 30-40% 就进入
- 如果玩家用"先走外圈再回来"的策略，会发现步数对不上
- 角落约束是自然产生的（棋盘形状 + 关键数字位置），不是硬塞的

**坏关风险：**

- 角落只是一个"先到一下就行"的点，没有真正锁住
- 角落锁太紧变成唯一可能路线，推理变成 trivial
- 和 close pair 混在一起，玩家分不清是在绕行还是在解锁角落

---

### 5.4 LATE_GAME_TRAP

**玩家看到什么：**

前半段（前 2-3 段）的数字位置故意诱导一种"合理"的绕行。玩家如果按这个直觉走，走到后半段会发现剩下的空间不够走完。

**玩家要思考什么：**

- 这个绕行看起来合理，但它会消耗掉后面必须用的格子吗？
- 如果前面"省着走"，后面空间够不够？
- 有没有一段看起来可以绕，但实际上必须直走？

**好关标准：**

- 前半段的"诱饵路径"是真实合理的——不是故意做错的，而是玩家自然会产生的一种走法
- 诱饵路径走到一半（不是走完）才会发现空间不够
- 正确路径在每一步都是"看起来不那么自然但最终通畅"
- 陷阱是空间约束产生的，不是靠隐藏信息（所有关键数字一开始就可见）

**坏关风险：**

- 诱饵路径太明显 → 玩家第一反应就是错的 → 变成惩罚性设计
- 诱饵路径一上来就走不通 → 没有"以为自己对了"的体验
- 正确路径太 obscure → 玩家试了所有可能最后蒙对的
- 变成"背板"关而不是推理关

---

### 5.5 BALANCED_DEDUCTION

**玩家看到什么：**

棋盘上有 3+ 个区域（或独立的推理单元），每个区域都有自己的步数约束。所有区域的约束加起来恰好等于总步数。玩家不能只看一个区域，必须同时协调所有区域。

**玩家要思考什么：**

- 区域 A 需要 8 步，区域 B 需要 6 步，区域 C 需要 10 步 → 但它们之间有先后依赖
- 如果先走 A，那么 B 的入口会不会被 A 的路径堵住？
- 如果先走 B，A 还能不能走完？
- 最终只有一种区域访问顺序能满足所有约束

**好关标准：**

- 每个区域的步数约束是独立且清晰的
- 区域之间的依赖不是"唯一通道"这么简单，而是"A 的出口位置决定 B 的起点是否可达"
- 玩家可以逐个区域验证约束，但必须全局协调才能找到解
- 最终解是唯一的

**坏关风险：**

- 约束太多 → 唯一解太明显 → 不需要推理
- 约束太少 → 多解 → 不确定哪条是对的
- 区域划分不直观 → 玩家感受不到"多区域"的存在
- 变成了 arithmetic puzzle（算步数）而不是 spatial puzzle（空间推理）

---

### 5.6 MULTI_REGION_ROUTE

**玩家看到什么：**

棋盘上有 3-5 个自然区域，关键数字标记了每个区域的入口和出口。整条路线需要按一定顺序穿过这些区域。

**玩家要思考什么：**

- 区域的访问顺序是什么？
- 哪些区域必须连续访问（中间没有别的区域）？
- 哪些区域之间必须插入其他区域（因为步数约束）？
- 进入和离开每个区域的位置在哪里？

**好关标准：**

- 区域在视觉上有辨识度
- 区域访问顺序是核心推理，不是 close pair 的副产品
- 至少有一个"先经过但不进入"的区域（因为进入时机未到）
- 正确顺序是唯一解

**坏关风险：**

- 区域顺序太明显 → 不需要推理
- 关键数字都标在区域中心 → 区域入口/出口不明确
- 变成"猜顺序"而不是"推理顺序"

## 6. Medium 应避免的 Easy 套路

| Easy 套路 | 在 Easy 中的出现频率 | Medium 控制策略 |
|-----------|-------------------|---------------|
| CLOSE_PAIR（曼哈顿近但需绕行） | 6/10 关（60%） | 每关 ≤ 2 个 close pair 段，且不再作为主推理模式 |
| LONG_SEGMENT（单段 ≥ 9 步） | 3/10 关（30%） | 单段控制在 6-10 步，不做 11+ 步超长段 |
| CENTER_START（中心起点） | 3/10 关（30%） | 每 3-4 关最多 1 关中心起点，增加边缘/角落起点 |
| EQUAL_LENGTH（等长段主题） | 1/10 关（10%） | 不再做专门等长段主题关，段长自然变化 |
| 纯蛇形/扫描形路径 | demo-01 | 不使用纯蛇形/扫描形，全部用手工不规则路径 |

## 7. 7×7 Prototype 范围

### 7.1 Prototype 定义

Prototype 的目的是**验证 7×7 是否值得作为 Medium 主方向**，不是提前做 Medium 关卡。

| 项目 | 决策 |
|------|------|
| 关卡数量 | 2 关 |
| 棋盘尺寸 | 7×7 |
| 关卡类型 | 1 个 AREA_SPLIT + 1 个 BALANCED_DEDUCTION |
| 关卡来源 | 手工设计（不使用程序生成） |
| 可见关键数字 | 11-15 个（含 1 和 49） |
| UI 接入 | 暂不接 |
| 正式入库 | 暂不入 |
| 验证方式 | 离线唯一解验证 |
| 试玩方式 | 内部试玩 |
| 目标 | 验证 7×7 是否明显优于 5×5，是否值得继续投入 |

### 7.2 Prototype 成功的含义

Prototype 成功 **不等于** Medium 正式启动。

Prototype 成功只意味着：

- 7×7 的推理体验被验证为可行且有价值
- 可以进入"正式设计 Medium 10-15 关"的下一阶段
- 可以开始考虑 UI 适配和正式入库方案

### 7.3 Prototype 失败的含义

Prototype 失败只意味着：

- 7×7 在目前的设计能力下不适合作为 Medium
- 需要回到 5×5 方案，或探索其他方向
- 不是 Hidden 模式的失败

## 8. Prototype 关卡设计要求

每个 7×7 prototype 关卡应满足：

### 8.1 基础规则

- 棋盘 7×7，覆盖全部 49 格
- 四向正交移动，不重复访问
- keyNumbers 必须包含 1 和 49
- 每段步数 = 下一关键数字 - 当前关键数字

### 8.2 设计原则

- 可见关键数字 11-15 个（对应 34-38 个隐藏格，~69-78% 隐藏）
- **不靠** close pair 作为主要推理手段（可以有但不超过 2 段）
- **不靠** long segment 硬绕
- **至少体现一个** Medium archetype（AREA_SPLIT / BALANCED_DEDUCTION 等）
- 路径不能是蛇形、扫描形、纯螺旋形
- 必须手工设计路径（不是程序生成）
- 必须能用人话解释"为什么这关是 Medium，不是 Easy 5×5"

### 8.3 质量要求

- 唯一解验证通过
- 推理链清晰（设计者能写出"玩家应该这样想"的推理步骤）
- 避免试错型过关（玩家不需要靠猜）
- 最好有"恍然大悟"的时刻（不是"终于试出来了"）

## 9. Solver / Validator 评估边界

### 9.1 当前状态

- `dev/hidden-medium-feasibility.js` 是一个**临时 feasibility 评估脚本**
- 该脚本证明了：
  - 7×7 路径可以手工/程序生成
  - 在 ~73% 隐藏密度下（11-15 可见 / 49 总格），正交 DFS solver 可以快速验证唯一性
  - 7×7 的推理空间可以支持 AREA_SPLIT 等 archetype
- 但该脚本 **不是正式 validator**

### 9.2 当前脚本的局限

- 随机 key placement 结果不稳定（每次运行结果不同），不能作为最终质量依据
- "找到 2 个解就停止"的 solver 适合判断"非唯一"，但不能保证"所有 7×7 场景下 solver 都不会超时"
- 蛇形/扫描形路径的 solver 性能极好（<1ms），但不规则路径的最坏情况性能未经充分测试
- 缺少 archetype 检测、close pair 占比检测、起点分布检测等质量检查

### 9.3 正式 validator 需求（未来，本阶段不实现）

正式入库前需要的验证工具：

| 功能 | 说明 |
|------|------|
| 唯一解验证 | 当前 DFS 逻辑已可用，需增加超时和 fallback |
| 多解检测 | 不仅要判断"非唯一"，还要在合理时间内输出"至少 2 个解" |
| 相似度分析 | 检查新关与已有关卡的路径 / key number 分布是否过于相似 |
| archetype 标注 | 自动检测关卡属于哪些 archetype |
| 起点 / 终点分布检查 | 避免某种起点位置过于集中 |
| close pair 占比检查 | 标记 close pair 段占比 > 30% 的关卡 |
| long segment 占比检查 | 标记单段 ≥ 10 步的关卡 |

### 9.4 风险声明

虽然当前评估显示 solver 性能良好（~75% 隐藏下 < 1ms），但以下场景未充分测试：

- 高度不规则路径 + 低密度关键数字（< 10 个 visible）的组合
- 多条"几乎对"的路径（solver 需要深入搜索才排除）
- 极端 long segment（单段 15+ 步）的剪枝效果

**因此不能将 solver 性能描述为"完全没有风险"。**

## 12. 成功标准

### 12.1 Prototype 成功标准

7×7 prototype 视为成功，需满足：

| 标准 | 说明 |
|------|------|
| 体验差异 | 玩家能感知到与 5×5 Hidden 的明显不同——不只是"更大"，而是"推理方式不同" |
| 不依赖重复套路 | 不依赖 close pair 作为主要推理手段 |
| archetype 落地 | 至少一个 prototype 有清晰可辨识的 AREA_SPLIT 或 BALANCED_DEDUCTION |
| 唯一解 | 验证通过 |
| solver 性能 | 在 1 秒内完成唯一性验证（非严格指标，但应合理） |
| 设计成本 | 单个 7×7 手工关卡设计时间在可接受范围（建议 < 2 小时/关） |
| UI 风险 | 确认 7×7 渲染在当前 UI 框架下基本可行（不需要大改） |

### 12.2 Prototype 失败标准

以下任一情况出现，视为 prototype 失败：

| 标准 | 说明 |
|------|------|
| 只是更大的 5×5 | 玩家感受不到推理方式的变化 |
| 只是更绕 | 核心体验还是"这两个点很近，绕远路走" |
| 推理链不清 | 设计者无法写出清晰的推理步骤 |
| 太依赖试错 | 玩家靠尝试不同走法来过，而非靠推理 |
| validator 不稳定 | 多次运行结果不一致，或无法可靠判定唯一性 |
| UI 过于拥挤 | 7×7 在现有 UI 中不可用（格子太小、文字叠在一起） |

## 13. 最终建议

### 推荐结论

> **建议进入 7×7 Hidden Medium prototype 阶段，但不进入正式关卡入库。**

### 理由

1. **5×5 推理天花板已接近**：Easy 10 关已覆盖 5×5 上所有有意义的推理类型，继续 5×5 只能产出 5-8 关同质化内容
2. **7×7 推理空间质变**：从"两个点之间怎么绕"升级为"整张棋盘的区域和通道怎么安排"，这是 Hidden 模式应有的难度层级
3. **可行性初步验证通过**：solver 性能良好，路径可手工设计，关键数字密度合理
4. **风险可控**：prototype 只有 2 关，不接 UI，不修改现有代码，不 commit
5. **prototype 失败代价低**：最坏情况是回到 5×5 方案，损失 2 个手工关卡的试错成本

### 下一步

```
Step 1: 设计 2 个 7×7 手工 prototype 关卡
         → AREA_SPLIT ×1 + BALANCED_DEDUCTION ×1
         → 使用离线 solver 验证唯一性
         → 文件放在 dev/ 目录，不接入正式游戏

Step 2: 内部试玩验证
         → 验证推理体验是否明显优于 5×5
         → 验证 archetype 是否可感知
         → 评估手工设计效率
         → 评估 UI 适配风险

Step 3: 根据试玩结果决策
         → 成功 → 进入"Medium 10-15 关正式设计 + UI 适配"阶段
         → 失败 → 评估是否需要回到 5×5 或探索其他方向
         → 不确定 → 追加 1-2 个 prototype，覆盖更多 archetype
```
