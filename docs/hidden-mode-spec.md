# Hidden / 极简线索 玩法规格

> 本文档是 Hidden（极简线索）模式的**唯一权威玩法规格文档**。
> Easy / Medium / Hard 各阶段的玩法设计均更新在本文件中。
> 不再新增单独的 `hidden-medium-design.md` / `hidden-hard-design.md` 等分离文档。

---

## 1. 玩法定位

### 1.1 核心身份

| 维度 | 说明 |
|------|------|
| 对外玩法名 | **极简线索** |
| 内部 modeId | `hidden` |
| 一句话说明 | 线索极少，推理极深。从寥寥几个关键数字还原出唯一路线。 |
| 模式入口副标题 | 根据有限的数字线索，推理整条路径 |
| 关卡内 HUD 提示 | 关键数字分段推理 · 全局唯一解 |
| 独立色系 | 橘色/琥珀系（`#e0a870` / `#d4955e`） |

### 1.2 三个关键定位

1. **不是 Classic hard+。** 不是把 Classic 的 hidden 比例从 50% 提到 80%。仅仅是"隐藏更多数字"不构成新玩法。

2. **不是 Flow / Numberlink 换皮。** Hidden 只有一条连续路径，不分多条颜色线，不引入颜色系统，没有多条独立路径。

3. **是分段关键数字推理。** 玩家根据棋盘上极少的几个关键数字，按顺序分段连接，每一步都受段长（数字差值）和全盘覆盖约束，最终还原唯一正确的一笔画路线。

### 1.3 核心句

> **线索极少，推理极深。**

## 2. 通用规则

### 2.1 移动规则

| 规则 | 设置 |
|------|------|
| 移动方向 | **正交四向**（上下左右），不允许斜向 |
| 跨格 | 不允许 |
| 路径重复 | 不允许（每个格子只能经过一次） |
| 全盘覆盖 | **必须覆盖**棋盘上的每一个格子 |
| 起点 | 必须从关键数字 `1` 所在格子开始 |

所有阶段（Easy / Medium / Hard）共用此移动规则。

### 2.2 关键数字与段长约束

棋盘中少量格子显示数字，其余格子均为空白。

**段长约束：** 如果两个连续关键数字为 `a` 和 `b`（a < b），则从 `a` 所在格子到 `b` 所在格子的路径必须恰好执行 **`b - a` 次移动**。

该段包含 **`b - a + 1` 个数字位**（含起点 `a` 和终点 `b`）。若从已被占用的起点 `a` 继续前进，该段新增 `b - a` 个格子。

整条路线从 `1` 到 `N×N`，总共 **`N×N - 1` 次移动**，覆盖 **`N×N` 个格子**。

示例（5×5）：

```text
关键数字：1、6、12、18、25（5×5，共 25 格）

第 1 段：1 → 6   差值 5，执行 5 次移动（该段含 6 个数字位，新增 5 个格子）
第 2 段：6 → 12  差值 6，执行 6 次移动（该段含 7 个数字位，新增 6 个格子）
第 3 段：12 → 18 差值 6，执行 6 次移动（该段含 7 个数字位，新增 6 个格子）
第 4 段：18 → 25 差值 7，执行 7 次移动（该段含 8 个数字位，新增 7 个格子）

总移动次数：5 + 6 + 6 + 7 = 24
总格子数（数字位）：25
```

### 2.3 必须显示的数字

- **起点 `1`：** 必须显示。这是可用性底线——玩家必须知道从哪里开始。
- **终点 `N×N`：** 必须显示。知道终点位置帮助全局推理，降低纯猜测的可能。
- **中间关键数字：** Easy（5×5）建议 3-4 个（总计 5-6 个）；Medium（7×7）建议 9-13 个（总计 11-15 个）。

### 2.4 必须唯一解

每个关卡在同一组关键数字下，必须只有一条路径满足所有约束（段长、全盘覆盖、不可重复）。如果存在多条路径，该关卡不能入库。

## 3. 与现有玩法的区别

### 3.1 对比 Classic

| 维度 | Classic | Hidden |
|------|---------|--------|
| 推理方式 | **局部推进：** 看到下一个数字，走过去 | **分段推理：** 从有限关键数字推导完整分段路径 |
| 可见数字比例 | 约 50%–60% | **约 20-24%（Easy）、约 22-31%（Medium）** |
| 核心约束 | 下一个数字是确定的（但不一定可见） | **段长 + 空间 + 全盘覆盖三重约束** |
| 玩家的核心问题 | 「下一个数字藏在哪里？」 | **「这一段恰好 N 步的路有几条？哪条留了后续空间？」** |
| 失败模式 | 连错 → 扣血 | 路线封死 → 发现约束矛盾 → 回退重推 |
| 解题节奏 | 步进式，一步一个判断 | **段进式，一段一次规划** |
| 对周围信息的依赖 | 高（靠相邻数字判断） | **低（只能靠段长和棋盘边界）** |

> Classic 是「看清楚下一步」；Hidden 是「想清楚一整段」。

### 3.2 对比 Diagonal / Portal

Hidden 是独立玩法，不与 Diagonal / Portal 共享关卡数据、进度存档或结算逻辑。

| 维度 | Hidden 与其他玩法的关系 |
|------|----------------------|
| 关卡数据 | 独立文件，手工设计 |
| 进度存档 | 独立 localStorage key |
| 结算 | 无分数/金币/星级，纯通关验证 |
| 道具 | 不开放 |
| 排行榜 | 不接入 |
| 移动方式 | 正交四向（与 Classic 一致） |

## 4. UI / UX / 结算

- 独立橘色/琥珀色系（`#e0a870` / `#d4955e`）

| 项目 | Easy（5×5） | Medium / Hard（7×7） |
|------|-----------|------------------|
| 模式名 + 关卡号 | `极简线索 · 第 N 关` | 同 |
| 进度显示 | `路径 x / 25` | `路径 x / 49` |
| 分数/金币 | 不显示 | 不显示 |
| combo/streak | 不显示 | 不显示 |
| 道具栏 | 不显示 | 不显示 |

### 4.3 WinPanel

- 标题：`推理完成！`
- 配色：橘色/琥珀色（`text-[#f0a070]`）
- 统计：显示关键数字数量、用时、路径覆盖
- 无星级、无金币奖励、无 reward trail SVG
- 详情区标题：`推理数据`

### 4.4 关卡选择页

- 逐关解锁（与 Classic / Diagonal 一致）
- 通关后标为已完成（无星级）

## 6. Validator / Analyzer 标准

正式入库前，每关必须通过以下验证：

| 检查项 | 说明 |
|--------|------|
| 唯一解验证 | DFS/BFS 遍历，确认在当前关键数字集合下仅有一条有效路径 |
| 路径覆盖验证 | 路径长度 = N×N，所有格子恰好访问一次 |
| keyNumbers 验证 | 必须包含 1 和 N×N，keyNumbers 严格递增 |
| 段长验证 | 每段移动次数 = b - a |
| 相似度分析 | 新关与已有关卡的路径形状 / key number 分布相似度低于阈值 |
| 起点/终点分布 | 同阶段内起点/终点位置不集中于同一类型（如过多中心起点） |
| close pair 占比 | 标记 close pair 段占比 > 40% 的关卡（Medium 阶段 ≤ 30%） |
| long segment 占比 | 标记单段 ≥ 12 步的关卡（Medium 阶段避免） |

当前正式验证入口是 `npm run validate:hidden`，辅助分析入口是 `npm run analyze:hidden`。

**已完成。** Easy 10 关 (`hidden-demo-01` ~ `hidden-demo-10`) 已阶段性收口。

### 7.2 Easy 定位

Easy 阶段的目标是**教会玩家关键数字分段推理**——让玩家理解"段长约束"和"全局唯一解"的核心机制。

### 7.5 5×5 推理天花板

5×5 棋盘的限制不在于"关数做不够"，而在于**推理空间的维度不足**：

| 限制 | 原因 |
|------|------|
| 无法做真正的区域分割 | 25 格划分 2 个区域已经是极限，最多 1 个通道 |
| close pair 容易重复 | 绕行空间有限，只有少数几种拓扑结构 |
| long segment 容易变成硬绕路 | 长段就是绕着走，缺少"区域选择"的空间意义 |
| 缺少前段对后段的不可逆影响 | 路径短（25 步），前 10 步很难封锁后 10 步 |
| 同质化风险高 | 继续 5×5 → 更多 close pair → 更多 long segment → 玩家感觉"又是绕" |

### 7.6 Easy 后续

- Easy 10 关保持不变
- demo-10（`[1,7,13,19,25]`）作为 Easy 收尾关保留
- 不在 Easy 阶段大量追加 5×5 关卡

## 8. Medium 阶段：7×7

### 8.1 当前状态

**已完成。** Medium #11–#30 共 20 关已入库，使用 7×7 棋盘。

### 8.2 为什么 Medium 不能继续 5×5

如果继续 5×5，只能新增 5-8 关，且推理类型高度重复：

| 可做类型 | 预计关数 | 局限 |
|---------|---------|------|
| CORNER_LOCK（简化版） | 2-3 | 角落只有 4 个，约束浅 |
| LATE_GAME_TRAP（显式化） | 1-2 | 板面过小不够隐蔽 |
| BALANCED_DEDUCTION（简化版） | 1-2 | 最多 2 区域，深度有限 |
| 起点/终点变体 | 1-2 | 换了起点形状不变 |

**不可在 5×5 上实现：** AREA_SPLIT、MULTI_REGION_ROUTE、真正的 BALANCED_DEDUCTION。

> **5×5 不应该作为 Hidden Medium 的主路线。**

### 8.3 7×7 的核心价值

7×7 带来的不是"尺寸 ×2"，而是**推理空间的维度增加**：

| 维度 | 5×5 Easy | 7×7 Medium |
|------|---------|------------|
| 棋盘格数 | 25 | 49 |
| 路径长度 | 25 | 49 |
| 可见关键数字 | 5-6 | 11-15（建议） |
| 分段数 | 4-5 | 8-14 |
| 平均段长 | 5-6 | 3-7 |
| 可划分区域 | ≤2 | 3-4+ |
| 可设置通道 | 0-1 | 1-3 |

**五个质变点：**

| 质变 | 说明 |
|------|------|
| 从点到区域 | 5×5 上每个关键数字只是"一个点"；7×7 上关键数字可以标记"区域入口/出口" |
| 从局部绕行到全局规划 | 5×5 绕行是局部的；7×7 上前半段的路径选择会影响后半段哪些区域还能访问 |
| 从单通道到多通道 | 7×7 可以有 2-3 个狭窄通道，形成"必须从 A 区经过通道去 B 区"的约束 |
| 从单约束到复合约束 | 多个 close pair + 多个 long segment 可以自然交错，不需要人工堆砌 |
| 从"走对"到"安排顺序" | 核心推理从"这一段怎么绕"变成"这几个区域按什么顺序走" |

> **不只是走够步数，而是安排整张棋盘的通过顺序。**

### 8.4 7×7 Medium 目标体验

**玩家应该感受到的：**

1. 看到一张大棋盘，上面散布着十几个数字
2. 判断"棋盘有哪些区域？数字分布在哪些区域？"
3. 规划：哪些区域必须先去，哪些必须后去？
4. 识别通道：哪些格子是连接两个区域的唯一通道？
5. 警惕死路：角落和边缘如果太晚去，会不会已经无法进入？
6. 全局协调：这段多走 2 步会不会导致后一段少 2 步空间？
7. 最终：不只是"每一段都走对了"，而是"整张棋盘的空间被合理分配了"

**玩家不应该感受到的：**

- 只是"更大的棋盘上更多 close pair"
- 只是"更长的一段要绕更远"
- 靠试错而不是推理就能过
- 看不出"为什么这关是这个难度"

### 8.5 Medium Archetype

以下 5 个 archetype 是 Medium 阶段的核心关卡类型。单关可以同时属于多个 archetype。

#### AREA_SPLIT（占比建议 30-40%）

**核心推理：区域分割 + 通道选择。**

棋盘被自然分为 2-3 个区域，关键数字分布在各个区域。区域之间有 1-2 个狭窄通道。

玩家需要判断：哪些关键数字在哪个区域？先走完区域 A 再去区域 B，步数够不够？错误的区域顺序会导致某段步数不够。

**好关标准：**
- 分区在视觉上有辨识度（玩家一眼能看出"这是两片"）
- 通道数量恰好（1-2 个），位置明确
- 至少有一个关键数字标记通道入口或出口
- 正确的区域访问顺序是唯一解

**坏关风险：** 分区边界模糊玩家看不出 / 通道太多没有瓶颈 / 分区变纯摆设 / 实际推理还是 close pair

---

#### CORNER_LOCK（占比建议 20-30%）

**核心推理：角落/死角必须提前进入。**

棋盘的四角或内部死角有关键数字。这些位置一旦错过就很难回来。

玩家需要判断：哪个角落必须在路线的前 30-40% 就进入？如果先走外围再回角落，步数对不对？

**好关标准：**
- 至少有一个角落必须在路线前段进入
- "先走外圈再回来"的策略会导致步数对不上
- 角落约束是自然产生的（棋盘形状 + 关键数字位置）

**坏关风险：** 角落只是"先到一下就行"没有锁住 / 角落锁太紧推理变 trivial / 和 close pair 混在一起

---

#### LATE_GAME_TRAP（占比建议 10-20%）

**核心推理：前半看似合理，后半被封死。**

前半段的关键数字位置故意诱导一种"合理"的绕行。玩家如果按这个直觉走，后半段会发现空间不够。

**好关标准：**
- "诱饵路径"是真实合理的——玩家自然会产生的一种走法
- 诱饵路径走到一半才会发现空间不够
- 正确路径"看起来不那么自然但最终通畅"
- 陷阱是空间约束产生的，不是靠隐藏信息

**坏关风险：** 诱饵太明显变成惩罚性设计 / 一上来就走不通 / 正确路径太 obscure / 变成背板关

---

#### BALANCED_DEDUCTION（占比建议 20-30%）

**核心推理：多区域同时约束，全局协调。**

棋盘上有 3+ 个区域，每个区域都有自己的步数约束。玩家不能只看一个区域，必须同时协调所有区域。最终只有一种区域访问顺序能满足所有约束。

**好关标准：**
- 每个区域的步数约束独立且清晰
- 区域之间的依赖是"A 的出口位置决定 B 的起点是否可达"
- 玩家可逐个区域验证，但必须全局协调
- 是 spatial puzzle（空间推理）而非 arithmetic puzzle（算步数）

**坏关风险：** 约束太多 → 解太明显 / 约束太少 → 多解 / 区域划分不直观 / 变成纯算术

---

#### MULTI_REGION_ROUTE（占比建议 20-30%）

**核心推理：区域遍历顺序。**

棋盘上有 3-5 个自然区域，关键数字标记了每个区域的入口和出口。整条路线需要按一定顺序穿过这些区域。重点是"区域顺序"而不是"单点绕行"。

**好关标准：**
- 区域在视觉上有辨识度
- 区域访问顺序是核心推理，不是 close pair 的副产品
- 至少有一个"先经过但不进入"的区域
- 正确顺序是唯一解

**坏关风险：** 区域顺序太明显 / 关键数字都在区域中心入口不明确 / 变成"猜顺序"

---

### 8.6 Medium 应避免的 Easy 套路

| Easy 套路 | Easy 出现频率 | Medium 控制策略 |
|-----------|-------------|---------------|
| CLOSE_PAIR（曼哈顿近但需绕行） | 6/10 关（60%） | 每关 ≤ 2 个 close pair 段，不再作为主推理模式 |
| LONG_SEGMENT（单段 ≥ 9 步） | 3/10 关（30%） | 单段控制在 6-10 步，不做 11+ 步超长段 |
| CENTER_START（中心起点） | 3/10 关（30%） | 每 3-4 关最多 1 关中心起点 |
| EQUAL_LENGTH（等长段主题） | 1/10 关（10%） | 不再做专门等长段主题关，段长自然变化 |
| 纯蛇形/扫描形路径 | demo-01 | 全部使用手工不规则路径 |

### 8.8 Legacy Notes：Prototype 关卡设计要求（已完成）

- 棋盘 7×7，覆盖全部 49 格
- 四向正交移动，不重复访问
- keyNumbers 必须包含 1 和 49
- 可见关键数字 11-15 个
- **不靠** close pair 作为主要推理手段（可以有但不超过 2 段）
- **不靠** long segment 硬绕
- 至少体现一个 Medium archetype
- 路径不能是蛇形、扫描形、纯螺旋形
- 必须手工设计路径
- 必须能解释"为什么这关是 Medium，不是 Easy 5×5"
- 唯一解验证通过
- 推理链清晰（设计者能写出"玩家应该这样想"的推理步骤）

### 8.9 Solver / Validator 评估边界

- 当前正式验证入口是 `npm run validate:hidden`。
- 当前辅助分析入口是 `npm run analyze:hidden`，覆盖相似度、archetype、起点/终点分布、close pair、long segment、shape tracing 等风险检查。
- Validator / analyzer 不能替代人工试玩判断；它们只保证合法性和辅助识别质量风险。
